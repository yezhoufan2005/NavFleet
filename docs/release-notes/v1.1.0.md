# NavFleet v1.1.0 · 前端焕新后的基准版

面向 **AGV / 巡检车 / 无人搬运车**的只读实时监控平台。车辆只需向 MQTT broker 发布遥测，其余环节由系统完成：字段归一化、告警派生、最新快照与时序落库、WebSocket 广播、前端呈现。

**v1.0.0 是第一个对外基准包，这一版是前端焕新之后的新基准。** 后端数据链路与 1.0.x 同源且向后兼容；变的是操作员看到的那一层，以及支撑它的工程结构。

## 这一版换了什么

v1.0.0 的前端是项目最初的手搓 demo 演进而来：12 个 SFC 全部没有 `lang="ts"`（约 2,300 行逻辑在 `vue-tsc` 视野之外）、零图表组件、单一视口、信息架构是「一个塞满的仪表盘 + 三个附属页」。

这一版把它整套换掉，**旧的那套冻结保留、随时可一行回滚**：

|            | v1.0.0                             | v1.1.0                                              |
| ---------- | ---------------------------------- | --------------------------------------------------- |
| 控制台     | `frontend/`（`navfleet-frontend`） | **`frontend-next/`（`navfleet-console`）**          |
| TypeScript | 渐进迁移，11 个 SFC 未纳入         | **全量**，所有 SFC 带 `lang="ts"`                   |
| 路由       | hash（`/#/`），4 个页面            | **web history，9 条产品路由**                       |
| 样式       | 原生 CSS                           | **Tailwind v4 + Reka UI**，CSS 变量令牌双主题       |
| 图表       | 无                                 | **ECharts**，懒加载（只有曲线 / 回放两个 tab 会取） |
| 响应式     | 单一视口                           | **1024 / 1440 / 1920 / 2560 四档**，含墙面看板字号  |
| 共享逻辑   | 前后端各一份                       | **`packages/fleet-core`**，两套前端共用             |

### 新的信息架构

- **总览** —— 默认落地页（1.0.0 没有对应页面）：在线设备、活跃消息、GPS 覆盖、编队四张卡，待处理项按严重度列出车名并直达该车，两个时钟分开显示（浏览器相对时间 + 服务端绝对时间）
- **设备** —— 列表 ⇄ 地图两个视图，按车队规模自动选择，选择被记住
- **设备详情** —— 新增页面，四个 tab：实时（报码解读 / 位姿 / 车辆状态，**枚举文案回来了**，控制模式与挡位不再是裸数字）· 曲线 · 历史回放 · 告警史
- **消息** —— 严重度分桶、设备筛选、来源标签、搜索、批量确认，**筛选条件写在 URL 里**（一个视图可以粘给同事）
- **管理** —— 系统状态（后端 / 快照 / MongoDB / MQTT 四项依赖逐项自述）· 场景（逐个探测地图资源是否可取得）
- **报表 / 大屏** —— **诚实的占位页**，写明施工中与对应的 PR 号，不是空白页

### 运维侧

- **Alertmanager 补齐** —— 此前 13 条告警规则一直在评估、一直在 fire，而 Prometheus 没有 `alerting:` 段、compose 里没有接收端。现在有了分组 / 去重 / 抑制 / 静默；**出厂接收器故意是空的**，配置邮件或 webhook 之前不外发，理由写在配置文件头部
- **`/docs`** —— 同源自带 Swagger UI（无 CDN），在鉴权门之后
- **`scripts/verify-stack.sh`** —— 起整栈 + **56 条断言**，全过才返回 0，可直接当验收门禁或 cron
- **MongoDB 钉 7.0** —— 8.0+ 在 Linux 内核 6.19–7.0.13 上拒绝启动（SERVER-121912），而本项目一行代码都不需要 8.0

## 系统构成

```
车辆 / 模拟器 ──MQTT──▶ Mosquitto ──▶ 后端（zod 校验→归一化→告警派生）
                                        │
                            ┌───────────┼───────────┐
                            ▼           ▼           ▼
                      内存快照     MongoDB     REST + WebSocket
                                （快照/时序/告警）        │
                                                    Nginx ──▶ Vue 3 控制台
```

- **后端**：Node **>= 22** + TypeScript + Express 5，`ws`、`mqtt`、`mongodb`、`pino`、`zod`、`prom-client`
- **前端**：Vue 3 + Vite + Pinia + vue-router（web history）+ Tailwind v4 + Reka UI + ECharts
- **部署**：Docker Compose，`nginx` / `web` / `backend` / `mongo` / `mosquitto` 五个服务，三段网络隔离（`data` 段 `internal: true`，Mongo 无出网能力），外加 TLS / 监控 / 备份 / 回滚四个叠加文件

`web` 的服务名取的是**角色**而不是实现 —— 换用哪一套控制台只是一行 `dockerfile:`。

## 能力

| 能力       | 说明                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------ |
| MQTT 接入  | 主题模板可配置；snake_case / camelCase 双写兼容；zod 校验后入库，被拒消息计入指标                            |
| 状态归一化 | 增量上报自动与历史值合并，不会因未上报字段而清空；`lidar` 定位在 `fusion` 缺失时回退                         |
| 告警派生   | 提示 / 预警 / 告警报码 + 低电量、离线等规则                                                                  |
| 三类地图   | GPS（高德）、栅格 / 点云场景图、Lanelet2 路网（服务端解析 `.osm`）                                           |
| 历史回放   | 基于时序集合的时间轴回放，可变速、可拖拽进度                                                                 |
| 鉴权       | JWT access + refresh（refresh cookie 限定在 `/api/auth` 路径）、分层限流。**角色分权见下面的边界说明**       |
| 可观测性   | 分级健康探针、Prometheus 指标、request-id 贯穿日志、预置 Grafana 16 个面板与 **13 条**告警规则、Alertmanager |
| 运行期配置 | 车队 / 车辆 / 编队 / 场景走 JSON 热加载，改完即生效，无需重启或重建镜像                                      |
| 无障碍     | WCAG 2.1 A + AA，axe-core 在 CI 中审计 **12 条路由 × 4 个视口 × 明暗两套主题**                               |

## 范围边界（有意为之，非待办）

- **只读监控**：不含控制下发。下发指令与监控是两种安全模型，混在一个进程里会让两者都变脆。
- **不做多租户**。
- **不做水平扩展**：状态在单进程内存中，目标场景是内网单实例（一台主机、几十到数百台车）。

## 快速开始

```bash
cp deploy/.env.example deploy/.env    # 至少填 MQTT 双口令、JWT_SECRET、ADMIN_PASSWORD
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
```

打开 <http://127.0.0.1:8080/> 登录。或者一步到位、连断言一起跑：

```bash
scripts/verify-stack.sh               # 起栈 + 演示数据 + 56 条断言，跑完把栈留着
```

容器镜像：

```
ghcr.io/yezhoufan2005/navfleet-backend:1.1.0
ghcr.io/yezhoufan2005/navfleet-console:1.1.0
```

> **`navfleet-frontend` 停在 1.0.x，不再发布。** 它装的是 v1.0.0 那套控制台，而这一版部署的是新的；继续用同一个名字推 1.1.0 会让 registry 里的标签说谎。回滚不依赖 registry —— 回滚叠加文件从源码本地构建。
>
> 镜像为 `linux/amd64`。前端的高德地图 Key 是**构建期**变量，需在发布前配置为仓库 secret；缺它时 GPS 面板显示「未配置 Key」，其余功能不受影响。

## 已知边界

**这一版最需要说清的一条：RBAC 是名义上的。** 数据模型里有 `admin` / `operator` / `viewer` 三个角色，登录、JWT、`requireRole` 中间件都在，但**三个角色的实际权限相同** —— `requireRole` 全仓库只有一处调用，且那条路由默认关闭。也没有用户管理接口，账号只能由环境变量种子出一个管理员。准确的说法是「**口令保护的看板**」，真 RBAC 与用户体系是 1.2.0 的内容。v1.0.0 的说明曾把这写成「完整的 RBAC」，属于过度承诺，已更正。

其余：

- **告警确认只存在浏览器 localStorage** —— 不落库、不跨人、无操作人无时间。页面上明说了这一点
- **报码字典不存在** —— 现存报码只是演示常量；设备详情页会诚实标注「该报码不在当前字典中」
- **报表与大屏是占位页**
- **MQTT 摄入无背压上界**（队列有上限并计数丢弃，但 broker 灌得足够快时仍会持续丢）
- **`prom-client` 上游已废弃**，待 `@prometheus-io/client` 有采用度后替换
- **Lanelet2 解析不过滤 `delete="true"`** —— 示例网络 88 条 lanelet 中 46 条带该标记，仍会绘制
- **axe 的 `incomplete` 桶未断言** —— 半透明与渐变表面落入该桶而不产生违规，仍需人工审阅
- **冻结的 `frontend/` 有 12 个 SFC 未加 `lang="ts"`** —— 这**不是待办**：那一套已冻结，不会再迁移
- **一批工程门禁尚未启用**（type-aware lint、`--max-warnings 0`、`noUncheckedIndexedAccess`、eslint 10、vitest 5），排在 1.1.0 之后独立执行
