# 前端功能等价基线（Phase 11A）

**这份文件是 Phase 14 的验收 checklist。** 新前端上线的条件不是"看起来更好"，而是这份清单里标了
「保留」「改造」的每一项都能核销。

盘点范围：12 个 SFC（2,537 行）+ 8 个 composable + store（761 行）+ 22 个 CSS partial（2,580 行），
逐文件读取，不靠记忆。所有条目都可回溯到 `file:line`。

## 怎么用

- `[ ]` → `[x]` 表示新前端已实现且经核对。
- **改造**项要在核销时写明"改成了什么、为什么"，不能悄悄降级。
- **废弃**项要在核销时确认"确实不需要"，而不是忘了做。
- 第 9 节是盘点中发现的**缺陷**：新前端要修掉，**照抄就是失职**。

## 0. 盘点纠正了三处此前的错误认知

写在最前面，因为 ROADMAP 的 11A 条目就是按错的认知写的：

1. **仪表盘没有筛选器、搜索框、排序控件。** 全文件零 `<input>`/`<select>`/`<label>`，唯一的筛选维度
   是编队选择，排序是硬编码的 deviceId 升序且用户不可改（`stores/fleet.ts:258-262`）。
   ROADMAP 11A 写的"每一个交互态、空态、快捷键"里，**快捷键一个都不存在**。
2. **没有告警抽屉。** `assets/styles/alert-drawer.css` 仍被 `main.css:11` 引入，但 `.alert-drawer` /
   `.drawer-scrim` 的标记在任何 `.vue` 里都不存在——**这是一批死 CSS**。ROADMAP 里"告警抽屉"一项作废。
3. **store 返回 28 个键，不是 30。** ROADMAP 11E 的数字错了，已在本文件第 8 节逐个列出。

另外两处小修正：两个地图组件的 a11y 属性全部来自基线提交，**不是** axe 补的（axe 那次改的是三个视图
和 CSS）；`RosSceneMap.vue:248-249` 有一条失效注释，说 `deviceExtentBounds` 供 `effectiveWorldBounds`
取景用，但后者从不引用它，真实消费者只有 `focusSelectedDevice`。

## 3. ROS 场景地图（`RosSceneMap.vue` 594 + `useSvgViewport.ts` 706）

> **这一节是新前端最大的技术风险。** `useSvgViewport` 是 v1.0.0 里花三次尝试才定位到根因的文件，
> 且覆盖率只有 **1.07%**。Phase 13A 的决定是**原样搬、不重写**——下面的条目因此主要是"搬过去之后
> 要验证仍然成立"，而不是"照着重新实现"。

**核销（Phase 13 收口 · 2026-08-31）：这一节最危险的失败模式没有发生。**
3.6 的 `hasMeasuredPanel` 与 3.7 的 `rebaseOffsetsToBounds` **都在，而且时机正确** —— 不是"找到了

**丢的是另一类东西：视觉编码。** 4 处能力损失 + 一批静默的视觉降级，逐条见表，汇总在节末。

- **最大点数输入框删掉，并且不发 `limit`。** 它的 `min/max` 因为没有 `<form>` 从不生效，而服务端
  无论如何按自己的 `MAX_HISTORY_POINTS` 硬夹 —— 所以这个控件让你填 5000、安静地给你 500。
  不发 `limit` 意味着由部署的上限说话；代价是前端不知道那个上限是多少，于是改为**如实报出实际

  更准确。留一个语义与三个按钮重叠的按钮，只是多一种到达同一处的方式。
- **reverse 改成显式排序。** 依赖 newest-first 是对后端顺序下的一个赌注；Mongo 路径确实是
  `sort({ts:-1})`，但内存回退是另一条代码路径。排序是断言，reverse 是赌注。
- **窗口的结束是那一分钟的结束，不是它的开始。** `datetime-local` 的值是一个*分钟*，而
  `slice(0, 16)` 会把 `now` 抹掉最多 59 秒 —— 于是「最近 1 小时」请求的窗口在一分钟前就结束了，
  最新的采样被安静地丢掉。这条是浏览器套件抓到的（滑块 `max="1"`，6 条只回来 2 条），单测看不见，
  因为没人会想到去断言"结束时间不早于现在"。v1.0.0 有同一处取整。
- **toast 改成空态与失败态。** toast 会滚走，而这两件事都要在人**正在看的地方**说 —— 那是地图区。
