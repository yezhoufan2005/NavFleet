# NavFleet 开发规范

本文是项目的房规：写代码、写文案、写文档时都按它来。规则描述的是**目标写法**——遇到与本文不符的旧代码，
改过来，不要照抄。流程（环境、命令、分支、PR、发版）在 [CONTRIBUTING.md](../CONTRIBUTING.md)；领域名词的
定义在 [glossary.md](glossary.md)。

## 0. 总则

- **两条红线**：**只读监控**（不向设备下发任何控制指令；经 admin API 写运维配置文件不算下发）、
  **单实例内网**（不做多租户、不做水平扩展）。取舍先对红线。
- **按现状描述，不按开发阶段。** 代码、注释、文档、提交说明都讲「现在是什么、为什么这样」，不出现
  「Phase N」「P1」「第 N 批」「item N」这类阶段编号，也不出现「(1.6.1)」「自 1.6.x 起」这类版本标注。
  来历看 git history。
- **不硬写会变的数字。** 车辆数、场景数、断言条数、测试条数、路由数、job 数都会变；需要时指向它的来源
  （如「示范车队见 `config-runtime/`」）。
- **一个概念一个名字、一个主题一处讲。** 名字以 [glossary.md](glossary.md) 为准；同一件事别在两份文档里
  各写一遍，另一处写一句话加链接。
- **只解决要解决的问题。** 不为想象中的需求加抽象、开关、兼容层；已声明但只实现了特例的能力，倾向端到端补齐。

## 1. 注释

- **一律英文，写「为什么」**：意图、权衡、踩过的坑、不显然的约束。不写复述下一行代码的注释。
- 中文只出现在被引用的 UI 文案与术语里（如 `// shown as 「处理中」 in the list`）。不整段写中文注释，
  不在同一句里中英混写。
- 不写归属与历史：谁改的、哪天改的、哪个版本加的、「以前是 X，现在改成 Y」都不写。
- 不引用不存在的文件、函数、文档；改名或删除时一并改掉指向它的注释。
- 注释是会过期的事实：改代码时同步改注释；不把时效信息（「当前 LTS」「最近一次测得」）写成永久事实，
  需要保留的测量值写明它是何时、在什么条件下测的。
- 不留代码生成痕迹（`PLACEHOLDER_*`、`CHUNK_*` 等，`npm run check:markers` 会拦）。

## 2. 界面用词

界面文案（按钮、标题、提示、校验、空态、表头）照下表写。表外的新词先补进本表再用。

### 2.1 领域词

| 概念                             | 用                                                | 不用                     |
| -------------------------------- | ------------------------------------------------- | ------------------------ |
| 消息的大类                       | 消息（消息史、消息规则）                          | 用「告警」当大类         |
| 三档级别                         | 告警（critical）/ 预警（warning）/ 提示（notice） | 严重、警告               |
| 级别这一列 / 这个筛选            | 级别                                              | 严重度、消息等级         |
| 处置动作                         | 认领 / 释放 / 忽略 / 取消忽略                     | 确认、取消确认           |
| 处置状态                         | 待处理 / 处理中 / 已忽略                          |                          |
| 结案方式                         | 处理后消除 / 自动恢复 / 已忽略后消除              |                          |
| 能力 `alerts:ack` 的显示名       | 处理消息                                          | 确认消息                 |
| 被监控的对象                     | 设备                                              | 车辆、车                 |
| 设备上报的任务 / 报码 / 机体     | 设备任务 / 设备报码 / 本体                        | 车端任务、车端报码、车体 |
| Prometheus / Alertmanager 的告警 | 监控告警                                          | 单用「告警」             |

「车辆」只在讲物理车辆或 MQTT 接入协议时用（设备接入文档、`vehicles.json` 的字段说明）。

### 2.2 操作词

| 用                                                 | 不用       | 例外                       |
| -------------------------------------------------- | ---------- | -------------------------- |
| 新建{对象}                                         | 新增、添加 | 表单里加一行仍用「添加」   |
| 编辑                                               | 修改       | 「修改密码」               |
| 删除                                               | 移除       | 表单里去掉一行仍用「移除」 |
| 保存                                               | 提交       |                            |
| 取消（关闭对话框）                                 | 关闭       | 提示条与 × 按钮用「关闭」  |
| 危险操作的确认按钮写动词本身：删除、下线、重置密码 | 确认、确定 |                            |

### 2.3 反馈文案

| 场景               | 写法                                                                         |
| ------------------ | ---------------------------------------------------------------------------- |
| 操作进行中（按钮） | 保存中… / 删除中… / 导入中… / 登录中…；不用「处理中…」（与处置状态撞名）     |
| 操作成功（提示条） | 「{对象}已保存」「{对象}已删除」                                             |
| 必填校验           | 「请输入{字段}」「请选择{字段}」                                             |
| 加载失败           | 「{对象}加载失败，请稍后重试」；403 / 429 等走统一的错误映射                 |
| 首次加载（读屏）   | 「正在加载{对象}」                                                           |
| 后端不可达         | 「无法连接后端，数据可能不是最新」；**不得**显示成「全部正常」或「没有数据」 |
| 确实没有数据       | 「当前没有{对象}」                                                           |
| 筛选后为空         | 「没有符合当前筛选条件的{对象}」                                             |
| 结果被截断         | 「仅显示最近 N 条，缩小日期范围可查看更早的记录」                            |
| 删除确认           | 标题「删除{类型}「{名称}」？」，正文「此操作不可撤销。」                     |
| 导航待办角标       | 只数待处理的消息，写「待处理 N 条」                                          |

### 2.4 格式

- 日期筛选写「起始日期 / 结束日期」。日期显示 `YYYY-MM-DD`，时间显示 `YYYY-MM-DD HH:mm:ss`，24 小时制，
  统一经 `formatDateTime`；不在组件里各写一个 `toLocaleString`。
- 空值统一显示 `--`。
- 中文句子用全角标点（，。：；？！（）），引用界面上的名称用「」；省略号用 `…`（单个字符）。
- 中文与英文、中文与数字之间加一个空格（「GPS 覆盖」「12 台」）；`%`、`°` 与数字之间不加空格。
- 界面上不出现英文缩写或代码名（「未配置环境变量」而不是「未配 env」）；专有名词用正确大小写（MongoDB、MQTT、GPS）。

## 3. 文档写作

- 中文正文；代码、路径、命令、环境变量、标识符一律用反引号，保持半角。
- 破折号写「——」（两侧不加空格），少用；不用 emoji 当状态标记。
- 标题用短句；长篇参考文档（部署、配置参考、架构）可以编号，改编号时同步修所有锚点链接。
- 每个相对链接、每个反引号里的路径都必须真实存在。
- 默认值写清来源：「代码默认」与「compose 默认」不同时分两列写。
- 外部事实（某版本 EOL、某上游缺陷）写成策略加链接（「Node 版本以 `engines` 为准」），不写成会过期的日期句。

## 4. 前端（Vue 3 `<script setup>` + Pinia + Tailwind）

- **Props**：响应式解构带内联默认——`const { a, b = 默认 } = defineProps<{…}>()`。不用 `const props = defineProps(...)`，
  不用 `withDefaults`。解构出的 prop 在 `watch` / `computed` 之外读一次就失去响应性：需要跟随变化时放进 `computed`。
- **Emits**：具名元组——`defineEmits<{ "update:x": [T] }>()`。
- **组合式**：`use*` 前缀，`export const useX = () => …`，文件名与主导出同名。
- **异步取数防竞态**：用 `useLatestRequest`（或 `requestId` 守卫：取前自增、await 后比对、卸载时丢弃在途）。
  慢响应绝不能覆盖新的筛选或另一个对象的结果；卸载后的回调、定时器、观察器、图表实例都要清理。
- **分页**统一用 `useListPagination`；**搜索框**用 `UiSearchInput`；**分段选择**用 `UiSegmented`；**卡片外框**用 `UiCard`，
  不再手写 `rounded-md border border-border bg-surface-raised p-N`。
- **加载状态**只有三种，都在请求超过 200ms 后才出现（`useDelayedFlag`），快请求什么也不闪：
  1. **首次加载**（还没有数据）：`UiLoading`，按内容形状画骨架（`table` / `fields` / `cards` / `block` / `lines`），
     `label` 写「正在加载{对象}」；复合骨架只在第一块写 `label`。不直接用 `UiSkeleton`。
  2. **重新加载**（已有数据：筛选、刷新、翻页）：不清空、不换骨架，`UiBusyRegion` 包住内容并传 `busy`，
     它标 `aria-busy` 并点亮顶栏下沿的页面进度条（`usePageProgress`）。取数函数区分 `status`（首次）与 `refreshing`（再次）。
  3. **操作中**（保存、删除、导入）：按钮禁用，文案按 §2.3 写。
- **错误**：加载失败用 `role="alert"`；不要给每秒都在变的文字（倒计时、「N 秒前」）加 `role="status"`。
- **周期时钟**用 `useNowTicker`，不各自起 `setInterval`。
- **颜色**只用语义令牌（见 [design-system.md](design-system.md)）；组件里出现 `dark:` 或主题媒体查询，说明缺一个令牌。
- **间距**：单一步距 16px（`gap-4`），分区之间、同排卡片之间都用它；只有列表与其分页（`gap-2`）、卡内标题与正文
  （`gap-2`~`gap-3`）、行内图标与文字（`gap-1`~`gap-1.5`）更紧。卡片内边距只有两档：统计块与列表行 `p-3`，
  内容卡与图表卡 `p-4`（即 `UiCard` 的 `sm` / `md`）。样板页是消息史。
- **图表**：option 由纯 builder 生成（可无画布测试）；主题切换要重建 option（`useChartTheme` 监听）；每张图配数据表视图
  （颜色不是唯一通道）。画布只上下滚、不左右滚，横滚只留给数据表；排行图用 `TopNSelect`（5 / 10 / 20 / 全部），不写死
  Top-N；热力与顺序色阶走 `--color-heat-0..4`。快照式序列在 fetch 的 `.then` 里赋给 ref，不用 computed 读实时 store
  （避免每个 tick 重绘）。
- **文字超长与容器尺寸**：布局定尺寸，内容不撑容器。
  1. 宽度由栅格与列宽标准（`tableClasses`）决定，长文字只在盒子里换行或省略。
  2. 按内容类型选处理方式，用 `textClasses`（`lib/uiClasses.ts`）：读的内容（说明、建议）`body` 完整换行；扫的内容
     （名称、字段、单元格）`title` 两行、`field` / `cell` 一行后省略；标识（编号、ID、路径）卡片里任意处折行，表格里一行省略。
  3. 固定件不让位：徽标、标签、按钮、时间、数字 `fixed`；只有弹性的那一块承担挤压（`minmax(0,1fr)` 或 `min-w-0`）。
  - 读数（数字、坐标、时间）不截断，宁可换行；卡片里两列「标签 + 值」网格在窄卡里退成一列（`@container` + `@md:grid-cols-2`）。
  - 会省略的元素都加 `v-overflow-title`，只在真被截断时给悬停全文。
  - 同行卡片等高、不设固定最小高度；图表卡定高，切数据表不变高；对话框、下拉、面板内列表设最大高度并内部滚动。

## 5. 后端（Express 5 + MongoDB + TypeScript）

- Express 5 自动把 async 处理器的 reject 交给错误中间件：路由里不写 `try/catch + next(e)`，领域错误在 `app.ts` 的
  错误处理器里映射成状态码。
- 错误响应体：`{ error, detail?, issues?, requiredCapability?, requestId? }`。`error` 是客户端据以分支的稳定码，`detail`
  给人看（哪个字段、哪个引用），5xx 不带 `detail` 只带 `requestId`。不另起 `message` 之类的字段；确需额外字段时写进 OpenAPI。
- 入参一律 zod 校验，失败走 `respondValidationError`。权限只按能力判断（`requireCapability`），不按角色名；同一前缀的
  多个路由用 `router.use("/x", …)` 一次挂门禁。
- 配置文件只有一套解析器（`@navfleet/shared` 的 `parse*`），加载与写入都走它。整档写入走 `configRegistry.writeWholeConfig`
  （解析 → 原子写 → 重载 → 读回）；原子写统一用一个 tmp + rename 的 helper，失败时清 tmp。写配置之后 store 必须重载并广播。
- 外发重试统一用 `notify/retry.ts` 的 `withRetry`，失败折成 `AttemptOutcome`，从不抛。外发策略（汇总、升级、重发窗口）
  只在后端实现一份，模拟器复用它。
- 内存缓存（如 RBAC）的变更：快照 → 改内存 → `await persist()`，失败回滚（`persistWithRollback`）；内存不得领先磁盘。
- TTL 索引只在集合缺失时创建；保留期变更交给 `migrations/ttl.ts` 的 `reconcileTtls`。
- 时区：业务时区只有 `REPORT_TIMEZONE` 一个来源，经 `localTime.ts` 的 helper 计算；不写死 UTC+8。
- 环境变量在 `config.ts` 的 schema 里声明并校验，非法值启动即失败；新增变量同步 `deploy/.env.example` 与
  `deploy/docs/config-reference.md`。
- `/openapi.json` 是手维护的契约：新增或修改路由同步改；枚举取源头常量（`CAPABILITIES`、`AUDIT_ACTIONS` 等）。
- 只导出被其他文件使用的符号。日志用 `moduleLogger("<模块>")`，消息写英文。
- 停机顺序：先停止接收 HTTP / WebSocket，再刷写缓冲，最后关数据库。

## 6. 包边界

- `@navfleet/shared`（零依赖）：领域类型、线上契约（请求与响应的序列化形状）、前后端都要的纯逻辑——规则、报码表、
  RBAC、报表契约、配置解析器、归一化 helper、严重度排序。
- `backend` 与 `frontend` 都只依赖 shared，彼此不互相依赖。同一段纯逻辑不在两边各写一份：要两边用，就放 shared。
- shared 里的模块级默认（`DEFAULT_*`）按只读使用，不就地修改。

## 7. 报码

- 编码方案：首位是渠道（info `1xxx` / warning `2xxx` / error `5xxx`），第二位是子系统，码号不重复。
- 部署的 `config-runtime/codebook.json` 与内置表合并下发，可以覆盖同号条目。演示与测试发出的每个码都要能解析到标签。

## 8. 测试

- 每个 workspace 都有 vitest 覆盖率门槛（见各自的 `vitest.config.ts`），只升不降；掉了就补真正缺的用例，只有换了
  度量工具时才重定门槛。
- 测行为，不测类型：不写只断言存在性的测试、不写纯快照测试、不把被测单元本身 mock 掉。
- 时间相关一律用假时钟（`vi.useFakeTimers` 或注入 clock），不用真实 sleep 去越过防抖；全局 stub 在 `afterEach` 里还原。
- 交互找不到元素时要失败：用会抛错的查询，不用 `?.trigger()`。
- 核心逻辑必须有针对性用例：报表聚合（含时区与跨日边界）、摄入校验、每个写路由所需的能力、消息去重与处置
  （含乐观锁冲突）、外发重试、配置写入与回滚。
- 共用的构造器、假持久层、挂载 helper 放各自的 `test/helpers/`，不在每个文件里重写一份。
- e2e 在临时端口自起服务；落库的状态在用例之间经 API 撤销，不让一个用例的副作用泄漏到下一个。

## 9. 演示数据

- 演示数据要像真实运营：形态、频率、时长、因果照实际来，某一时刻覆盖率低是正常的；验收要的全覆盖另用演练剧本
  （`npm run sim -- scenario`）。
- 自洽：曲线按车有差异，消息与遥测对齐（电量偏低落在电量谷底）。
- 演示口令只从公开 seed 派生、拼接生成，不在仓库里出现字面量（秘密扫描会拦）。

## 10. 提交

- Conventional Commits：`<type>(<scope>): <中文摘要>`。
  - type：`feat` `fix` `perf` `refactor` `docs` `test` `build` `ci` `chore` `style` `revert`。
  - scope 用区域名：`frontend` `backend` `shared` `sim` `demo` `deploy` `e2e` `ci` `deps` `docs`；也可用页面或领域名
    （`alerts` `reports` `notify` `rbac` `devices`）。
- 摘要会原样进入 CHANGELOG：写用户能感知的效果，不写阶段、批次、版本号、负责人。
- 一个提交做一件事；格式化等机械改动单独提交。
