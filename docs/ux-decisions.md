# 界面组织的几个决定

控制台为什么这样排版——这些决定在实现期会被反复问到，记在这里，按现状陈述（不是候选对比，也不按阶段）。

## 按「谁在什么时候要做什么」分区，不按数据种类

一级分区是**总览 / 设备 / 消息 / 报表 / 用户 / 部署 / 系统**，每个分区自带二级标签（tab）。几条由此而来的决定：

- **大屏值班是一种模式，不是一个分区。** 它不可交互、无会话超时，所以是独立入口 `/wall` + kiosk 凭据，
  **不进主导航**——值班时没人会「导航到大屏」。
- **设备详情是详情路由 `/devices/:id`，不是一级项。** 从列表、地图、告警任何地方都能进；把「我们有设备
  这种数据」提成一级项是按数据分区，不是按任务分区。
- **历史回放是设备详情里的一个 tab，不是独立页。** 独立页的代价是查完实时还要重新选一次设备。
- **没有「设置」页。** 主题等个人偏好进用户菜单，连接诊断进「系统」分区。

## 导航：左侧栏三态 + 细顶栏

选侧栏而非顶栏，理由具体：**16:9 屏上垂直像素比水平稀缺**，而地图与 ECharts 曲线吃的正是高度。顶栏导航
要占掉 56–64px 通高，侧栏收起后只占 44px 通宽。面包屑由页面层级自动生成；跨分支跳转（告警 → 设备详情）
是常态，导航要支持从任意位置进详情。

## 其它

- **URL 用 web history 模式**（非 hash），路由可分享、可直达。
- **断点两端是平板与大屏，不是手机**：现场值班与工位使用是目标场景，不为手机竖屏优化。
- 旧 `/admin/*` 路径全部保留为重定向（分区重构后不打断已有书签），详见 README「页面地图」。
