# 术语表

NavFleet 的领域名词，以及它们在代码里的对应。界面、文档、注释都按这里的名字写；用词规则见
[conventions.md §2](conventions.md#2-界面用词)。

## 消息

| 术语               | 含义                                                               | 代码                                                                               |
| ------------------ | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 消息               | 平台根据设备上报与规则产生的一条事件记录，是告警、预警、提示的统称 | `alerts` 集合、`/api/alerts`                                                       |
| 告警 / 预警 / 提示 | 消息的三档级别，从重到轻                                           | `Severity`：`critical` / `warning` / `notice`（`packages/shared/src/severity.ts`） |
| 级别               | 上面三档之一                                                       | `severity`                                                                         |
| 活跃消息           | 尚未消除的消息                                                     |                                                                                    |
| 消除               | 触发条件不再成立，消息结束                                         | `alert.cleared` 事件                                                               |
| 消息史             | 已产生过的全部消息，含已消除的                                     | 消息分区的「消息史」标签                                                           |
| 消息规则           | 平台侧派生消息的阈值、开关与作用范围（如低电量、离线）             | `config-runtime/rules.json`                                                        |
| 报码               | 设备自己上报的状态码，按码号解读成文字与级别                       | `packages/shared/src/reportCodes.ts`、`config-runtime/codebook.json`               |
| 报码字典           | 内置码表与部署码表合并后的解读表                                   | 部署分区的「报码字典」                                                             |

## 处置

处置是值班人员对一条消息的线下处理过程在平台上的记录。平台只读，不向设备下发任何指令。

| 术语                                 | 含义                                                           | 代码                                                                                   |
| ------------------------------------ | -------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 待处理 / 处理中 / 已忽略             | 活跃消息的三种处置状态                                         | `AlertDisposition`：`unhandled` / `investigating` / `ignored`（`alertDisposition.ts`） |
| 认领                                 | 表示有人在处理，状态变为处理中                                 | `POST /api/alerts/claim`                                                               |
| 释放                                 | 放弃认领，状态回到待处理                                       | `POST /api/alerts/release`                                                             |
| 忽略 / 取消忽略                      | 标记为不需要处理，或撤销这个标记                               | `POST /api/alerts/ignore`、`/unignore`                                                 |
| 处理后消除 / 自动恢复 / 已忽略后消除 | 消息消除时按处置状态推导出的结案方式                           | `ALERT_CLOSE_DISPOSITION_LABELS`                                                       |
| 处理消息                             | 允许认领、释放、忽略的能力                                     | 能力 `alerts:ack`                                                                      |
| 冲突                                 | 两人同时处置同一条消息时，后到的一方收到版本冲突，需刷新后重试 | HTTP 409、`version` 字段                                                               |

## 设备与部署

| 术语                | 含义                                                                         | 代码                                             |
| ------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------ |
| 设备                | 被监控的一台车辆或机器人，界面上统一叫设备                                   | `DeviceSnapshot`、`config-runtime/vehicles.json` |
| 车辆                | 只用于物理车辆与 MQTT 接入协议的语境                                         |                                                  |
| 设备状态            | 由上报推导的运行状态：离线、急停、故障、遥控、充电中、任务中、异常中断、待命 | `getDeviceStatus`                                |
| 设备任务 / 平台任务 | 设备自己上报的任务，与平台侧编排的任务                                       | `deviceTask.ts`                                  |
| 编队                | 一组设备，带满编人数与所属场景                                               | `config-runtime/formations.json`                 |
| 场景                | 一块作业区域及其地图                                                         | `config-runtime/scenes.json`                     |
| 底图 / 路网 / 点云  | 场景地图的三种图层：栅格或矢量图片、Lanelet2 / OSM 路网、PCD 点云            | `scene-maps/`                                    |
| 运行期配置          | `config-runtime/` 下的 JSON，热重载；经管理界面写入，不需要重启              | `configRegistry.ts`                              |

## 数据与外发

| 术语            | 含义                                                                         | 代码                                                |
| --------------- | ---------------------------------------------------------------------------- | --------------------------------------------------- |
| 快照            | 全车队当前状态的完整一份                                                     | `fleet.snapshot` 事件、`GET /api/fleet/snapshot`    |
| 增量            | 某台设备状态变化后的推送                                                     | `fleet.delta` 事件                                  |
| 遥测            | 设备按秒上报的位置、速度、电量等                                             | `telemetry_ts` 时序集合                             |
| 小时汇总        | 按小时预聚合的遥测，报表从这里读                                             | `telemetry_hourly`                                  |
| 外发            | 把消息推送到企业微信、钉钉、邮件、Webhook 等外部渠道                         | `config-runtime/notify.json`、`backend/src/notify/` |
| 汇总发送 / 升级 | 外发的两种策略：一段时间内的消息合成一条发；无人处置的消息到时间后发给下一级 | `notify.json` 的 `digestSeconds` / `escalation`     |
| 定时报表        | 按计划生成并邮件发送的报表                                                   | `config-runtime/reports.json`                       |
| 监控告警        | Prometheus / Alertmanager 产生的运维告警，与消息无关                         | `deploy/prometheus/alerts.yml`                      |

## 账号与权限

| 术语       | 含义                                                                 | 代码                                            |
| ---------- | -------------------------------------------------------------------- | ----------------------------------------------- |
| 角色       | 内置三种（admin / operator / viewer），另可自定义                    | `UserRole`、`rbac.json`                         |
| 能力       | 权限的最小单位，路由按能力判断                                       | `CAPABILITIES`（`packages/shared/src/rbac.ts`） |
| 用户组     | 一组用户共享一组自定义角色                                           | `RbacGroup`（`packages/shared/src/rbac.ts`）    |
| 大屏       | 值班墙的只读展示模式，独立入口 `/wall`，用大屏账号登录、会话长期有效 | kiosk 账号                                      |
| 受保护账号 | 由 `ADMIN_USERNAME` 创建的初始管理员，别人不能停用、降级或删除       | `AdminUserView.protected`                       |

## 演示

| 术语     | 含义                                                         | 代码              |
| -------- | ------------------------------------------------------------ | ----------------- |
| 示范车队 | 仓库自带的演示配置                                           | `config-runtime/` |
| 模拟器   | 按真实运营节奏为示范车队产生上报的进程                       | `backend/sim`     |
| 回填     | 首次起栈时生成保留期内的历史数据，之后每次只补停栈期间的空档 | `sim catchup`     |
| 演练     | 按剧本在已知时刻注入极端情况，用于验收覆盖                   | `sim scenario`    |
